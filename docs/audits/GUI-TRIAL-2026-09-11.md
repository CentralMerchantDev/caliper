## 5. What this interface could not do that a terminal session would

- **The Bash tool's working directory does not persist between calls in this
  session**, despite its own tool description ("the working directory
  persists between commands"). Running `cd "C:/Code/sandbox-spike" && git
  status --short` inside one call worked correctly, but every subsequent
  call started back at `C:\Users\User` and needed its own `cd`/absolute
  path. In a real terminal, one `cd` at the start of the session would have
  been enough. This meant every shell command in this run either re-stated
  the full path or was chained with `&&` inside a single call.
- No interactive terminal was available to leave a long-running watcher
  (e.g. a dev server, a file watcher) attached across turns the way a real
  terminal session would; this did not matter for this run since BOUND fired
  before anything needed running, but it would have for B4/B5-scale work
  (mutation runs cited elsewhere in the plan take 15+ minutes each on this
  host).
- Everything else needed for this run — reading files, `git`, calling the
  process MCP tools — worked the same as it would from a terminal.
