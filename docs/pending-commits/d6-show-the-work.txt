source-edit path (D4) would show a player -- the code a model actually

failure this whole project exists to prevent: a failed check reading as a

How it is known to be fixed:

- public/stage-artefact.js, new. stageArtefact(stage, source, verdict) shapes
  one stream event; describeStageOutcome(artefact) returns
  ok: true | false | null -- deliberately never collapsed to a plain boolean,
  because "not yet checked" (an implement event fires before verify runs) is
  a real, different state from either a pass or a fail, and losing that
  distinction is the same failure-floor shape this project keeps finding
  elsewhere in different clothes.
- Deliberately did NOT touch src/changePipeline.ts (2,000+ live lines,
  already carrying real spend caps and gates) or index.html's existing stage
  rendering -- the same "prove the mechanism, defer the wiring" pattern
  D1/D2/D4 already used tonight, doubly warranted here since src/ is
  extended, never rewritten, and D4's own generate/verify path is not wired
  into that pipeline yet either.
- test/stageArtefact.test.ts (4): the artefact carries the source and verdict
  unaltered; a FAILED verify's description text matches /fail|refus/i and
  explicitly does NOT match /success|verified ok|passed/i; a passing verify's
  text names what was actually measured (a triangle count), not a bare "ok";
  an artefact with no verdict yet reads as ok:null, neither a pass nor a
  fail.
- Mutation `failed-verify-reads-as-failed` CAUGHT. Reports "verified ok" for
  a failed verdict regardless of what actually failed -- precisely
  failure-floor item 1, shipping an unverified change while reporting it as
