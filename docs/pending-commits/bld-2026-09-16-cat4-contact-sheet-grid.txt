CAT-4: the contact sheet reads as a grid -- the camera angle was the
defect, not the layout math.

WHAT WAS WRONG: docs/briefs/BLD-2026-09-16.md CAT-4 (PLAN.md 5.3,
CHECKLIST.md CAT-4): "put it on a grid rather than a diagonal strip in a
field of black... it already earned its keep: it is what made the scale
problem visible."

RE-GROUNDED BEFORE TOUCHING ANYTHING: read public/catalogue-contact-
sheet.html before assuming the grid needed rebuilding. It was already a
real grid -- `col = i % COLS, row = Math.floor(i / COLS)`, COLS=6, every
entry placed in a real row/column, no diagonal strip anywhere in the
layout math. The defect was the CAMERA: `camera.position.set(centerX -
dist, dist * 1.1, centerZ - dist)` offsets equally on BOTH x and z, a
45-degree isometric azimuth -- and a perspective camera at that angle
photographs any rectangular grid as a rotated DIAMOND, with the
viewport's own four corners left empty. That is exactly "a diagonal
strip in a field of black," produced by a real grid shot from the wrong
angle, not a fake grid.

THE FIX: camera offset on Z only now (x fixed at centerX), so grid rows
read as horizontal bands filling the frame's own width -- the diamond's
empty corners are gone. Elevation lowered from dist*1.1 to dist*0.55, a
real trade disclosed in the code comment: more top-down would fill the
frame even further but flattens height toward invisible, which is the
opposite of what this sheet needs once FIX-1 lands (the 6x height cap
removed) -- kept steep enough that a piece's own vertical extent still
reads.
