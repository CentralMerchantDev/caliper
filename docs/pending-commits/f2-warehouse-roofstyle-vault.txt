What was wrong. The prior session's F2b survey (commit c3bd9de) marked
bldWarehouse "clean" on the narrow test "is every params field genuinely
consulted" -- true, roofStyle IS read in an if/else. What that check did
not ask: does every declared VALUE of a consulted field produce distinct
geometry? It does not. `roofStyle = r3 < 0.4 ? "sawtooth" : r3 < 0.7 ?
"barrel" : "curved"`, but the else-branch built one identical flat roof
box regardless of which of "barrel"/"curved" was rolled -- confirmed by
direct reading of public/buildings.js's real bldWarehouse (not the dead
kit-style code), same file this whole checklist has already been working
against. This is the same defect CLASS the checklist's item 1 correction
named (a field computed and reported in `params` but not fully honoured by
the geometry), just a milder variant: consulted, but two of three labels
collapse to one output. Found by re-reading, not assumed from the earlier
"clean" verdict.

What changed. The else-branch now builds a real, per-building vault via a
partial CylinderGeometry -- the same idiom bldMidrise's "curved"
cornerTreatment already uses for a quarter-round corner (facadetextures.js
precedent, line ~1883), applied horizontally (rotateX) instead of
vertically. "barrel" (half-angle 0.55 rad) is a deeper arc than "curved"
(0.28 rad); both radius and rise are derived from the building's own real
width (bW/2 = R sin(halfAngle)), so the shape is correctly proportioned at
every cellW/cellD combination, not a fixed constant. totalH and LOD1's
roof-box height now track the style-dependent rise (`vaultRise`) instead
of the old fixed `roofH`, so the declared height stays an honest upper
bound and roof-mounted vents no longer sit embedded inside the taller
vault (checked directly: vent height previously used the fixed roofH,
which the vault's real apex height already exceeds).

A real geometry bug caught by the tests themselves, not by inspection: the
first version used `openEnded: false` (capped ends), which produced a
`geometry dips below ground (-23.23)` failure -- a closed partial-cylinder
cap is a triangle fan to the FULL circle's centre (radius 0), which for a
shallow arc built from a large radius sits far below the visible arc
itself, an artifact invisible for bldMidrise's small fixed-radius (1.4 m)
corner but a real defect at this vault's much larger, per-building radius.
Fixed to `openEnded: true`; the footprint-bounds test caught it on the
first run, before any manual visual check.

The gate, red first. Added a `positionFingerprint`-based test (matching
this file's own established convention for shapes with identical triangle
counts, e.g. bldTownhouse's bayStyle "full" vs "cantilever") --

differ in radius/angle, so a triangle-count assertion could not have
caught this defect. Also added four footprint-bounds cases (barrel/curved
at min and max cellW/cellD) to the existing "new shapes stay strictly
inside the declared footprint" test.
