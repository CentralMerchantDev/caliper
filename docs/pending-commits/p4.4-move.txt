P4.4 MOVE -- drag a piece to a new grid address, wiring board.js's existing
canPlace refusal to a cursor and to the player, refusal path tested first

WHAT WAS BUILT: public/move-piece.js's tryMove() -- a pure query, no
mutation -- asks a real, small, local board.js instance (the same
public/board-region.js localBoard() helper P4.3's neighboursOf now shares,
extracted rather than duplicated per this project's own standing rule
against a second answer to the same need) whether a piece would fit at a
destination cell. It does not re-decide fit: board.js's own canPlace
({ok:false, reason, blockedBy}) is the only authority, exactly as
Mark's brief named it ("wiring an existing refusal to a cursor, not writing
a new one"). moveEditFor() turns a successful result into world-model.js's
own exact move-op shape ({address, op:"move", payload:{x,z}}), matched to
layout.js's own placement.x/z convention (footprint centre, `(xMin+xMax)/2`)
so an overridden piece's render position means what a normal one's already
does.

world-render-3d.js's new _moveSelected(): calls tryMove, and on refusal
calls `this.onMoveRefused({reason, blockedBy, plotId})` -- NEVER a console
log, checked directly (test asserts no console.log/warn/error appears in
the method at all). On success it builds the real layer edit via
world-model.js's layerFrom() (public/apply-and-persist.js's own reference
pattern) and adds it to the real world.layers stack, then live-repositions
the piece in the current scene using P4.2/P4.3's own promote-out-of-the-
instanced-batch technique -- named as an approximation, not hidden: the Y
used for the live preview is heightAt(x,z), the bare ground height, not
footprint.js's own terrace/verdict-aware base a full rebuild computes. The
emitted layer edit is the authoritative position (city-render.js's own
override-move render path, already wired, reads it exactly); the live
reposition is a preview of it, not a second source of truth.

REFUSAL TESTED FIRST, AND DIFFERENTLY, PER THE BRIEF: scripts/_move-piece-
probe.mjs (same isolated-child-process pattern as P4.3's own probe, same
documented OOM reason) finds three real, distinct refusals against the real
26 km world -- moving building A onto building B's own real cell
("occupied", with a real blockedBy naming B), moving off the edge of the
world ("off-map"), and moving a plotId not on the board at all
("not-found") -- and asserts occupied and off-map read as DIFFERENT reasons,
not one generic refusal. Only after those three does the success case run:
a real free destination found by trying tryMove() itself against real
nearby offsets, not an invented coordinate.
