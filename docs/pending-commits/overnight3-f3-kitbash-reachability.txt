What was measured, and why every gap is what it is. The registry:
public/kitbash-parts.js holds 62 named geometry parts;
public/kitbash-recipe-map.js's DESIGN_RECIPE_MAP holds 40 named designs.
Two DIFFERENT reachability numbers exist for this kit, and conflating them
is exactly the defect this item asks to close:

1. Reachable from the kit's OWN internal harness (assembleBuilding's
   random assembly + all 40 named designs, exercised together) -- 57/62
   parts (92%), 40/40 designs (100%, each assembles real non-empty
   geometry). Already measured and gated since RUN2/RUN3
   (test/kitbashNamedDesigns.test.ts's own "GATE: registry coverage" test,
   unchanged tonight, reconfirmed passing). The 5/62 parts unreached even
   here (all `connector` category) are WHY: genuinely, mechanically
   unreachable given current content, not a bug -- a connector needs a
   design with two structural volumes to join; exactly one shaft part has
   a paired form (shaft-twin-atrium), and every design using it already
   has exactly one connector. Checked mechanically by this suite's own
   RUN3 test, which goes red the day a new twin-shaft design appears.

2. Reachable from the real PRODUCT world (what a visitor's browser
   actually loads, index.html/city.html -> city-render.js) -- 0/62 parts,
   0/40 designs. `public/city-render.js` has zero references to any
   kitbash export, confirmed by direct grep on THIS branch and on
   `b1-land` (`git show b1-land:public/city-render.js`, read-only, no
   checkout). WHY: never wired to product, anywhere -- this is NOT the F1
   pattern (wired on the other branch, just not merged yet); it is unwired
   on both branches, a whole disconnected subsystem, first named in
   docs/audits/K6-BUILDINGS.md's own "disconnected capability" section and
   never closed since. The real, rendered world is built entirely through
   a separate, parallel system (public/buildings.js's `building()`
   dispatcher).

A third, previously-uncategorised bucket, found while classifying the
gaps precisely rather than reporting one number: 4 of the kit's exports
(createRng, createChamferedRectShape, createBevelledExtrusion,
resolvePalette) classify as "unreachable" by the cross-file import graph,
which sounds like dead code and is NOT -- checked directly, all four are
called heavily WITHIN their own file (resolvePalette alone has 60+ call
sites in kitbash-parts.js). They are over-exported utilities, genuinely
load-bearing, just not imported from anywhere else. Exactly the "unreached
can mean several different things" case this item's own brief warned
about, using tonight's earlier deadExports finding (5 facade-textures.js
exports that turned out to BE the F1 capability itself) as the precedent.
