P4 knot, part 2 -- CLAUDE.md and public/index.html now carry real measured

WRONG, three separate stale claims, one shared cause: scripts/gen-test-count.mjs
refuses to publish public/index.html's test-count claim while any test is
red, and until part 1 of this fix (commit 82cec4e) the deliberately-red
origin-stability test made every run red permanently -- so CLAUDE.md's "How
to verify" line (1061), the page's own node-test claim (948) and, found
while chasing the same live measurement, the page's building-count claim
(17,105, stale against src/citySummary.generated.ts's already-regenerated
17,108) were all pinned to numbers a real run had long since moved past.

A second, independent defect found trying to fix the first: gen-test-count.mjs
captures its child test runner's entire stdout into one in-memory string
(execFileSync, encoding "utf8", not streamed) and forwards this process's own
env -- including NODE_OPTIONS -- to that child. A heap cap meant to bound one
process therefore bounds the parent AND the child independently: passing
--max-old-space-size=3072 authorised 3072 MB twice, not once, 6 GB combined
against a host that had 3.1 GB free at the time and had already crashed
twice overnight on memory. Measured directly: parent+child climbed past
1.5 GB combined in 25 seconds under that cap, against the ~1.3 GB in eight
minutes the single `node test/run.mjs` process this script wraps takes on
its own.

HOW EACH IS KNOWN TO BE FIXED:

1. scripts/gen-test-count.mjs gained --node-log <path> / --worker-log <path>,
   read a file already holding a captured run's stdout instead of spawning
   and re-capturing the suite itself. Default behaviour (no flag) is
   unchanged -- no existing caller breaks. This makes running the suite and
   recording what it measured two separable steps: run test/run.mjs ONCE,
   alone, output redirected straight to a file (one process, nothing
   buffering it a second time), then hand that file to this script.

2. Three real, isolated single-process suite runs were needed to get here
   safely, memory-monitored throughout (two of three killed mid-run when
   free system memory approached the point this host has previously
   crashed at -- not a defect in the suite, a real constraint of this
   sandbox tonight). The one that completed
   (fail 3: CLAUDE.md, the city-stats claim, the count-claim itself; pass
   1068; todo 1; skip 15) confirmed node:test's own `{ todo }` handling
   needs no help from this script: the origin-stability test's internal
   AssertionError still prints, and it is excluded from both the `ℹ fail`
   count and the failing-tests regex this script reads, by node:test itself
   -- "teach the generator to distinguish a failure from a todo" turned out
   to already be true, confirmed against real output rather than assumed.

3. public/index.html's #city-stat-buildings span (17,105 -> 17,108) and
   CLAUDE.md's own verification line (1061 -> 1087 node tests; 12 worker
   tests unchanged, vitest run standalone and confirmed 12/12) were updated
   by hand, since neither has a generator that writes them -- the same shape
   as gen-test-count.mjs's own claim-node-tests span, which script fixes
   are refused to do until the suite excluding the permanent todo is green.

4. A fourth full isolated run, all three fixes in place, confirmed exactly
   the target shape before publishing anything: 1087 tests, pass 1070,
   fail 1 (only "the test counts on the page are the test counts" -- the
   one case gen-test-count.mjs's own onlyTheCountClaim exemption exists
   for), todo 1, skip 15. `node scripts/gen-test-count.mjs --node-log
   /tmp/node-run3.log` then ran for real: the exemption fired, wrote
   test/testCount.generated.json (nodeFail: 1, the true measurement of that
   run, not a fabricated zero) and updated public/index.html's
   #claim-node-tests span to 1087, exactly as designed.

5. FINAL CONFIRMATION, watched directly, not assumed: a fifth full run,
   this time the actual `npm test` (typecheck + node suite + vitest) in one
   isolated capped process, completed with exit code 0 and the suite's own
   summary reading tests 1087 / pass 1071 / fail 0 / todo 1 / skipped 15 --
   the exact target this fix set out to reach. `npx tsc --noEmit` (part of
   npm test) clean.
