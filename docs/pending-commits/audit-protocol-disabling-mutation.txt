WRONG, in the protocol rather than in any one control: §5.3 already covers
a mutation that does not apply (wrong location, zero or multiple matches)
as INCONCLUSIVE, not a pass. It did not cover a mutation that applies
exactly once, exactly where intended, and STILL proves nothing, because a
source-text regex check cannot distinguish "present in the file" from
"reachable by the interpreter" -- commenting a line out or wrapping it in
`if (false) { ... }` removes neither.

This recurred three times in this session alone (recorded in test/
mutations.json's own notes for isolate-new-pick-restores and isolate-
hides-moved-pieces, and caught a third time before landing on the ignoreId
control), by the same author, the second and third time after the lesson
had already been learned once and written into a commit message -- proof
that writing it in one commit message was not enough to make it stick,
which is exactly the reason this file's §7 exists.

Recorded as a standing check: when watching a control red by hand-editing
source, the edit must remove or invert EXECUTABLE effect, never wrap it in
a disabled branch or comment.
