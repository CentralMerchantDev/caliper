## 5.5 EVERY IMAGE YOU PUT IN FRONT OF MARK CARRIES ITS OWN QUESTION

**New requirement, and it applies to CAM-1, GRD-1 and CAT-4's re-render.**

Mark, 2026-09-16: *"as long as I know what context it is asking for my opinion,
so that I am not giving opinions on things that it isn't asking for and might

This has cost real time twice. He judged `09-piece-count-20.png` as a look when
it was a throughput instrument. He judged `25-board-scene-pass.png` a dust bowl,
and it was not clear whether that answered *"did the fog improve"* or *"does this
read as a city"* — different answers leading to different next items.

**So: no image goes to Mark as a bare file path.** Each one carries five lines,
in the handover and in the commit message:

1. **What changed** — one line, this item only.
2. **The question** — the specific thing his eye is being asked to settle.
3. **What is NOT being asked** — known gaps already queued or planned, named so
   he does not spend an opinion on something already scheduled. This is the line
   that matters most and the one that has been missing.
4. **Your own read first** — so he is correcting a view rather than starting
   cold, and so a marginal improvement cannot be quietly presented as a pass.
5. **What follows either answer** — if yes, the next item; if no, the specific
   alternative. He should know the cost of each answer before giving it.

An image without those five lines is not ready to be judged, and sending one is
the same defect as a gate that states green without stating red —
`rule://standard-of-proof`.
