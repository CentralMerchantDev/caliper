    ⚙️ Engine Operations & Deterministic Spatial Rules

    Autonomous Change Pipeline

    • 🎯 1. Target Spatial Scope: Click any district, villa, atelier, or marina dock in 3D to set local spatial coordinates.
    • ✍️ 2. Plan: the request becomes a typed list of edits, each one checked against a schema before anything is applied.
    • ⚡ 3. Verify: the edit is applied to a copy of the world in a Workers isolate and checked for overlap and out-of-bounds placement. A check that did not run is never read as a pass.

    Production System Invariants (Regression Guardrails)

    • Rule 1 (Clearance & No Clipping): In-memory 2D footprint collision solver enforces minimum buffer clearance across all buildings and outdoor fixtures.
    • Rule 2 (Boundary Containment): Placements must strictly satisfy parcel envelopes — out-of-bounds additions are rejected before mutation.
    • Rule 3 (Financial Spend Ceiling): Enforced via Cloudflare Durable Object atomic reservation locks against $2/day, $7/week, $20/month caps.
    • Rule 4 (world edits are data, not code): A world edit is a set of schema-validated operations spliced into sentinel-delimited data blocks — no eval, no AST. Benchmark cycles are the opposite on purpose: model-written code is executed in a fresh Cloudflare Dynamic Worker isolate, because judging code by reading it is the failure this project exists to avoid.

    📐 System Architecture & Deterministic Safety

    CLOUDFLARE WORKERS V8 ISOLATE ARCHITECTURE

    The model never writes code that touches the world. It writes a list of edits; they are validated against a schema, applied to a copy, and the copy is checked before anything is kept.

    FIVE-STAGE PIPELINE, TWO HUMAN GATES
    1. Ground: Checks the request's premises against the real world structure, and refuses ones that rest on something untrue
    2. Plan: Emits a typed edit plus its own executable acceptance criteria — then Gate 1, where a person approves, rejects, or replies
    3. Implement: Applies schema-bounded ops to a cloned state graph inside a Workers isolate
    4. Verify: Runs the regression suite and the plan's criteria in the sandbox; a suite that did not run is never read as a pass
    5. Review: A different vendor's model reads the diff cold. Material findings go to a fix loop and then Gate 2, which never auto-approves

    WHAT HAPPENS TO WHAT YOU TYPE

    Your request is sent to Anthropic and OpenAI, who run the models this pipeline uses. It is held for up to seven days so a run parked at a gate can be resumed, then it expires. It is never shown to another visitor: the public run history stores the model's understanding of a request, not the text you wrote.

    Runs are counted per visitor. That counter is keyed by a salted hash of your address rather than the address itself, and is deleted after two days. Nothing else is stored, and there are no analytics or trackers on this page.

    Do not type anything confidential into a public demo — including this one.

    MARK FRASER · APPLIED AI, TORONTO · RESEARCH REPORT

    A system that only says yes when yes is true

    Does a verification loop substitute for model capability, and what does it cost?

    The Finding: Cost Asymmetry via Verification

    A Cloudflare Worker that generates structured changes with an LLM, executes them against hidden tests inside an isolated sandbox, and — if a test fails — surfaces exact feedback to the model for an in-loop repair. Tested across 32 single-function benchmark tasks across three difficulty tiers — including a novel tier of seven specs I wrote myself, one of which deliberately contradicts a formula every model has memorised — over 450 stored cycles and 3 models (cheapest, mid, and frontier):

    The Benchmark Finding: Across this 32-task benchmark (450 stored cycles), the cheapest model (claude-haiku-4-5) with one or two repair rounds reaches the same final pass rate as the frontier model (claude-opus-4-8), at roughly 36–41% of the cost per correct answer ($0.00345 vs $0.00908 per cycle, hard tier, n=21 cycles per model, measured 2026-08-26).

    Cost figures are modelled: observed token spend plus a modelled ~$0.002/cycle for the Dynamic Worker isolate. That modelled component is charged to both models equally, so it makes the gap look smaller than it is — strip it out and the ratio goes from 36% to about 20%. The number quoted above is the conservative one.

    What "frontier model" means here: three models were benchmarked on this task set — claude-haiku-4-5, claude-sonnet-5, and claude-opus-4-8 — but claude-opus-4-8 is a benchmark comparison point only. It does not run on any live path of the change pipeline described on this page (ground/plan/implement/fix route through Haiku and Sonnet; gpt-5.3-codex reviews) — see "Multi-Model Cross-Review" below. This ratio describes relative cost in a controlled benchmark, not a cost this system pays in production.

    Correcting my own headline

    An earlier version of this write-up said the cheap model matched the frontier model. That was two claims welded together, and only one of them survives the data.

    17 of the 18 core tasks hit 100% final pass for every model on every repetition. When everything passes, the benchmark has stopped measuring: it shows the loop repairs slips cheaply, and it shows nothing at all about quality, because capability was never stressed. The cost claim holds. The quality-equivalence claim was untested, and I have withdrawn it.

    The honest read: this measures cost per correct answer on tasks a small model can already do. Finding the ceiling needs a harder suite. That is the next experiment, not a footnote on this one.

    Spec Disagreement: Verification Fixes Slips, Not Intent

    On camel-to-snake, every model returned parse_http_response, while the test insisted on parse_httpresponse. A third repair attempt did not alter Sonnet’s or Opus’s output. Verification loops reliably correct syntactic or edge-case slips; they cannot resolve genuine divergences of semantic intent.

    Deterministic Safety & Edge Isolate Guardrails

    Two paths, two guarantees World edits never evaluate code: they are schema-validated ops spliced into sentinel-delimited data blocks, no eval, no AST. Benchmark cycles do the opposite on purpose — model-written code is executed in a fresh Cloudflare Dynamic Worker isolate, because judging code by reading it is the failure mode this project exists to avoid.
    Durable Spend Backstop Atomic spend ledger ($2/day, $7/week, $20/month caps) held in a single SQLite-backed Durable Object, so every reservation is serialised through one place and compare-and-set cannot race.
    Multi-Model Cross-Review Claude authors the plan and implementation; OpenAI Codex (gpt-5.3-codex) acts as an independent reviewer.
