    MARK FRASER · APPLIED AI, TORONTO · RESEARCH REPORT

    A system that only says yes when yes is true

    Does a verification loop substitute for model capability, and what does it cost?

    The Finding: Cost Asymmetry via Verification

    A Cloudflare Worker that generates structured changes with an LLM, executes them against hidden tests inside an isolated sandbox, and — if a test fails — surfaces exact feedback to the model for an in-loop repair. Tested across 32 single-function benchmark tasks (3 difficulty tiers) and 3 models (cheapest, mid, and frontier):

    The Benchmark Finding: Across this 32-task single-function benchmark, the cheapest model (claude-haiku-4-5) with one or two repair rounds matches the frontier model (claude-opus-4-8) final pass rate, at roughly 36–41% of the observed cost per correct answer ($0.00345 vs $0.00908 per cycle). (Note: Task suite measured single-function repair rather than holistic model capability divergence).

    Spec Disagreement: Verification Fixes Slips, Not Intent

    On camel-to-snake, every model returned parse_http_response, while the test insisted on parse_httpresponse. A third repair attempt did not alter Sonnet or Opus's output. Verification loops reliably correct syntactic or edge-case slips; they cannot resolve genuine divergences of semantic intent.
